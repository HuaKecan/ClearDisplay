## 临时虚拟屏端到端验证

Release 应用的 `--virtual-smoke` 已实际通过，观察结果如下：

1. 创建独立辅助进程持有的虚拟 HiDPI 屏。
2. 读取到真实逻辑 1600 × 900，渲染 3200 × 1800。
3. 实际切换该临时屏到 1280 × 720 HiDPI。
4. 未确认，独立 DisplayRescue 到期恢复原虚拟屏模式并清除恢复记录。
5. 停止虚拟持有进程，屏幕移除。
6. 测试前后原两块物理屏的模式与布局快照一致。

测试过程中观察并修复了本机 CG 模式缓存问题：新屏 active，但先前查询过模式的进程看不到它的 CGDisplayMode；全新进程可以。实际枚举与切换使用一次性的显示服务辅助进程，不用演示数据代替。

## 状态栏与轻量化

- 原生 NSStatusItem + NSMenu，按显示器、HiDPI/标准分辨率、尺寸、刷新率分组，标记当前模式。
- `--menu-inspect` 基于真实两块显示器生成菜单结构，265 个原生菜单项（含子菜单/分隔），230 个自定义操作全部连接有效选择器；原生 `submenuAction:` 由 AppKit 自行处理。
- 菜单中的分辨率选择覆盖 223 个去重后的真实模式（外接 209 + 内置 14）；更多尺寸折叠、刷新率单独成子菜单。
- 工具未获取到顶部系统状态栏弹出区域的独立截图，菜单视觉位置和物理屏清晰度仍保留用户实际验收。可通过 `--menu-inspect` 在自己的电脑上生成菜单树。
- 默认无控制窗口、无空闲恢复定时器；窗口关闭释放 SwiftUI 树；菜单切换使用 AppKit 小确认面板。显示服务仅执行操作时启动，虚拟持有进程仅在创建虚拟屏后运行。
- 菜单栏空闲只读测量：10.013 秒内累计 CPU 时间保持 0.48 秒，测量 CPU 0.0%；最终 RSS 30.42 MiB；DisplayRescue / DisplayVirtualHost 存活数为 0。
- 短时本机样本，不是长时间或其他机型的保证。可通过 `scripts/measure-idle.py` 重新采样。

## 通用分享包

- 主程序、`DisplayRescue` 和 `DisplayVirtualHost` 均包含 `arm64`、`x86_64` 两种架构；两种架构的最低系统版本均为 macOS 14.0。
- ZIP CRC 和重新解压后的 `codesign --verify --deep --strict` 校验通过。
- 从重新解压的分享包运行 Apple 芯片版只读枚举，发现两块显示器和 223 个去重后的显示模式。
- 本机缺少 Rosetta 运行环境；Intel 版运行检查返回 `Bad CPU type in executable`，因此仅确认交叉编译和架构结果，未确认 Intel 真机行为。
- 包含中文说明、MIT 许可和本地签名的应用；未做 Apple Developer ID 公证。
